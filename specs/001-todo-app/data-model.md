# Data Model: To-Do List App

**Feature**: 001-todo-app
**Date**: 2025-10-24
**Storage**: IndexedDB with LocalStorage fallback

## Overview

The to-do list app has a single primary entity: **Task**. This represents a single to-do item with its associated metadata. The data model is intentionally simple to support the core CRUD operations without unnecessary complexity.

---

## Entity: Task

### Description

Represents a single to-do item that users create, complete, edit, and delete. Tasks are stored locally in IndexedDB and persist across browser sessions.

### Schema

| Field | Type | Required | Constraints | Description |
|-------|------|----------|-------------|-------------|
| `id` | number | Yes (auto) | Auto-increment, unique | Primary key, generated by IndexedDB |
| `title` | string | Yes | 1-500 characters | The task description/content |
| `completed` | boolean | Yes | true/false | Whether the task is marked as done |
| `createdAt` | number | Yes | Unix timestamp | When the task was created (milliseconds) |
| `updatedAt` | number | Yes | Unix timestamp | When the task was last modified |

### Example Instance

```json
{
  "id": 42,
  "title": "Buy groceries",
  "completed": false,
  "createdAt": 1729785600000,
  "updatedAt": 1729785600000
}
```

### Validation Rules

Based on functional requirements from spec.md:

| Rule | Requirement | Implementation |
|------|-------------|----------------|
| **VR-001: Title required** | FR-008: Prevent empty titles | `title.trim().length >= 1` |
| **VR-002: Title length** | FR-001: Min 1, max 500 chars | `1 <= title.length <= 500` |
| **VR-003: Completed is boolean** | FR-003: Binary state | `typeof completed === 'boolean'` |
| **VR-004: Timestamps valid** | Data integrity | `createdAt <= updatedAt` |
| **VR-005: ID is positive** | IndexedDB requirement | `id > 0` (auto-generated) |

### State Transitions

Tasks have a simple binary state model:

```
┌─────────────┐
│   Created   │ (completed: false)
│ (Incomplete)│
└──────┬──────┘
       │
       │ markComplete()
       ├─────────────────────┐
       │                     │
       ▼                     │
┌─────────────┐              │
│  Completed  │              │ markIncomplete()
│(completed=true)            │
└──────┬──────┘              │
       │                     │
       └─────────────────────┘
```

**State Transitions**:
1. **Create** → Task starts as incomplete (`completed: false`)
2. **markComplete()** → Sets `completed: true`, updates `updatedAt`
3. **markIncomplete()** → Sets `completed: false`, updates `updatedAt`
4. **edit()** → Modifies `title`, updates `updatedAt`, preserves `completed` state
5. **delete()** → Removes task from storage permanently

## IndexedDB Schema

### Database

**Name**: `TodoAppDB`
**Version**: 1

### Object Store

**Name**: `tasks`
**Key Path**: `id` (auto-increment)

### Indexes

| Index Name | Field | Unique | Purpose |
|------------|-------|--------|---------|
| `by_completed` | `completed` | No | Fast filtering by completion status (FR-009) |
| `by_created` | `createdAt` | No | Ordering tasks by creation date (FR-002) |

### Store Configuration

```javascript
const dbConfig = {
  name: 'TodoAppDB',
  version: 1,
  stores: {
    tasks: {
      keyPath: 'id',
      autoIncrement: true,
      indexes: [
        { name: 'by_completed', keyPath: 'completed', unique: false },
        { name: 'by_created', keyPath: 'createdAt', unique: false }
      ]
    }
  }
};
```

## Data Access Patterns

### Pattern 1: Create Task

**Operation**: Insert new task
**Index Used**: None (insert only)
**Expected Performance**: O(1) - ~1-5ms

```javascript
// Input
{
  title: "Buy groceries",
  completed: false,
  createdAt: Date.now(),
  updatedAt: Date.now()
}

// Output (after insert)
{
  id: 42,
  title: "Buy groceries",
  completed: false,
  createdAt: 1729785600000,
  updatedAt: 1729785600000
}
```

### Pattern 2: Get All Tasks

**Operation**: Retrieve all tasks ordered by creation date (newest first)
**Index Used**: `by_created` (reverse order)
**Expected Performance**: O(n) - ~10-50ms for 1000 tasks

```javascript
// Query
getAllTasks({ orderBy: 'createdAt', direction: 'desc' })

// Output
[
  { id: 100, title: "Most recent", ... },
  { id: 99, title: "Second recent", ... },
  { id: 98, title: "Third recent", ... }
]
```

### Pattern 3: Filter by Status

**Operation**: Retrieve tasks by completion status
**Index Used**: `by_completed`
**Expected Performance**: O(log n + m) where m = matching tasks - ~5-20ms

```javascript
// Query for incomplete tasks
getTasksByStatus(false)

// Output
[
  { id: 42, title: "Buy groceries", completed: false, ... },
  { id: 55, title: "Call dentist", completed: false, ... }
]
```

### Pattern 4: Update Task

**Operation**: Modify task title or completion status
**Index Used**: Primary key (id)
**Expected Performance**: O(1) - ~1-5ms

```javascript
// Input
updateTask(42, {
  title: "Buy groceries and milk",
  updatedAt: Date.now()
})

// Result
{
  id: 42,
  title: "Buy groceries and milk",
  completed: false,
  createdAt: 1729785600000,
  updatedAt: 1729785700000
}
```

### Pattern 5: Delete Task

**Operation**: Remove task by ID
**Index Used**: Primary key (id)
**Expected Performance**: O(1) - ~1-5ms

```javascript
// Input
deleteTask(42)

// Result
true (success)
```

## Storage Estimates

### Per-Task Storage

| Component | Size | Notes |
|-----------|------|-------|
| `id` | 8 bytes | Number (int) |
| `title` | 2-1000 bytes | UTF-16, avg ~100 bytes (50 chars) |
| `completed` | 1 byte | Boolean |
| `createdAt` | 8 bytes | Number (timestamp) |
| `updatedAt` | 8 bytes | Number (timestamp) |
| IndexedDB overhead | ~50 bytes | Index entries, metadata |
| **Total per task** | **~75-1100 bytes** | Avg ~175 bytes |

### Storage for 1000 Tasks

- **Minimum** (short titles): 75 KB
- **Average** (50-char titles): 175 KB
- **Maximum** (500-char titles): 1.1 MB

**Conclusion**: Well within IndexedDB storage limits (50MB+). LocalStorage fallback (5MB limit) can handle up to ~28,000 average tasks or ~4,500 maximum-length tasks.

## LocalStorage Fallback Schema

For browsers without IndexedDB support, use LocalStorage with this structure:

### Storage Key

`todoapp_tasks` (single key)

### Value Format

JSON array of tasks:

```json
[
  {
    "id": 1,
    "title": "Buy groceries",
    "completed": false,
    "createdAt": 1729785600000,
    "updatedAt": 1729785600000
  },
  {
    "id": 2,
    "title": "Call dentist",
    "completed": true,
    "createdAt": 1729785500000,
    "updatedAt": 1729785650000
  }
]
```

### ID Generation

Use `Math.max(...tasks.map(t => t.id)) + 1` for next ID.

### Performance Trade-offs

| Operation | IndexedDB | LocalStorage |
|-----------|-----------|--------------|
| **Read all** | O(n) indexed | O(1) read + JSON.parse |
| **Filter** | O(log n) indexed | O(n) array filter |
| **Update** | O(1) by key | O(1) read + modify + O(n) write all |
| **Delete** | O(1) by key | O(1) read + filter + O(n) write all |

**Note**: LocalStorage requires rewriting entire array on every change. Acceptable for <1000 tasks but not optimal.

## Data Integrity

### Constraints

| Constraint | Enforcement | Error Handling |
|------------|-------------|----------------|
| **Unique IDs** | IndexedDB auto-increment | Automatic, no collisions |
| **Title length** | Validation before save | Reject with error message |
| **Empty titles** | Validation before save | Reject with error message |
| **Valid timestamps** | Set on create/update | Automatic |
| **Boolean completed** | Type check | Reject with error message |

### Error Scenarios

| Error | Cause | Resolution |
|-------|-------|------------|
| **Quota exceeded** | Storage limit reached | Show error, suggest cleanup |
| **Corrupted data** | Invalid JSON in LocalStorage | Clear storage, start fresh |
| **Duplicate ID** | Manual data manipulation | Re-index with unique IDs |
| **Missing required field** | Schema mismatch | Apply defaults or reject |
